# SportSlot — бэкенд (Django)

Сервер для приложения бронирования спортивных площадок. Приложение на Flutter
отправляет запросы, сервер хранит данные в базе и проверяет правила.

## Зачем нужен сервер

* **Общие данные.** Игрок бронирует, а владелец видит бронь на своём телефоне.
* **Защита от двойной брони.** Один час нельзя продать двум людям.
* **Роли.** Игрок и владелец видят и могут делать разное. Правила проверяет сервер.
* **Безопасный вход.** Пароли хранятся в базе в зашифрованном виде.

## Запуск

```bash
cd D:\SportSlot.Backend
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py seed
python manage.py runserver
```

* `migrate` — создаёт таблицы в базе (файл `db.sqlite3`);
* `seed` — заполняет базу тестовыми данными (один раз);
* `runserver` — запускает сервер на http://127.0.0.1:8000.

Тесты: `python manage.py test`

## Как проходит запрос

Пример: игрок нажимает «Забронировать» в приложении.

```
Flutter  ->  POST /api/bookings/
              |
          core/urls.py        находит нужную функцию
              |
          core/views.py       проверяет роль, берёт данные из запроса
              |
          core/services.py    проверяет правила и создаёт бронь
              |
          core/models.py      сохраняет в базу данных
              |
Flutter  <-  JSON с готовой бронью (или {"error": "понятный текст"})
```

## Модели (таблицы)

* **Profile** — роль пользователя: `user` (игрок) или `owner` (владелец).
* **Venue** — площадка: название, адрес, цена, часы работы. Принадлежит владельцу.
* **Booking** — бронь: площадка, игрок, дата, с какого часа, сколько часов, цена, статус.
* **BookedHour** — один занятый час. У брони на 3 часа три таких записи.
* **BlockedSlot** — час, который владелец закрыл вручную.
* **Notification** — уведомление.
* **Favorite** — избранная площадка.

## Роли

| Что | Игрок | Владелец |
|---|---|---|
| Смотреть каталог и свободное время | да | да |
| Бронировать | да | нет |
| Отменить свою бронь (за час до начала) | да | — |
| Видеть брони | только свои | на своих площадках |
| Добавлять и менять площадки | нет | только свои |
| Закрывать часы, отменять чужие брони с причиной | нет | да, на своих площадках |

Проверка роли стоит в самом начале каждой функции в `views.py`. Чужую площадку
владелец вообще не найдёт: запрос `get_object_or_404(Venue, id=..., owner=request.user)`
вернёт «не найдено».

## Защита от двойной брони

Работает в три слоя:

1. **Проверка в `services.create_booking`:** все нужные часы должны быть свободны.
2. **Транзакция `transaction.atomic()`:** бронь и её часы сохраняются вместе или не сохраняются совсем.
3. **Ограничение базы `unique_together` в `BookedHour`:** база данных физически не даст
   записать «площадка + дата + час» дважды, даже если два человека нажмут одновременно.
   Тогда второй получит ошибку «Это время только что заняли».

При отмене брони записи `BookedHour` удаляются, и час снова свободен.

## API

Все адреса, кроме регистрации и входа, требуют заголовок
`Authorization: Token <ключ>`. Ключ выдаётся при входе или регистрации.

| Метод | Адрес | Что делает | Кто |
|---|---|---|---|
| POST | `/api/auth/register/` | Регистрация `{name, email, password, role}` | все |
| POST | `/api/auth/login/` | Вход `{email, password}` | все |
| GET | `/api/auth/me/` | Кто я | вошедший |
| GET | `/api/venues/?sport=Футбол` | Каталог площадок | вошедший |
| GET | `/api/venues/<id>/slots/?date=2026-10-30` | Часы дня и статусы | вошедший |
| POST | `/api/venues/<id>/favorite/` | Добавить/убрать из избранного | вошедший |
| GET | `/api/bookings/` | Мои брони (владельцу — брони на его площадках) | вошедший |
| POST | `/api/bookings/` | Создать бронь `{venue, date, hours}` | игрок |
| POST | `/api/bookings/<id>/cancel/` | Отменить бронь `{reason}` | игрок / владелец |
| GET | `/api/notifications/` | Мои уведомления | вошедший |
| POST | `/api/notifications/read/` | Прочитать все | вошедший |
| GET, POST | `/api/owner/venues/` | Мои площадки / добавить | владелец |
| GET, PATCH, DELETE | `/api/owner/venues/<id>/` | Показать / изменить / удалить | владелец |
| POST | `/api/owner/venues/<id>/block/` | Закрыть или открыть час `{date, hour}` | владелец |

Статусы часа в `/slots/`: `free` — свободно, `booked` — занято, `blocked` — закрыто
владельцем, `past` — время прошло.

Ошибки приходят в виде `{"error": "Текст для пользователя"}` с кодом 400, 403 или 404.

### Пример

```bash
# вход
curl -X POST http://127.0.0.1:8000/api/auth/login/ ^
  -H "Content-Type: application/json" ^
  -d "{\"email\": \"aibek@gmail.com\", \"password\": \"123456\"}"

# бронь на 18:00 и 19:00 (подставьте свой токен и дату)
curl -X POST http://127.0.0.1:8000/api/bookings/ ^
  -H "Authorization: Token ВАШ_ТОКЕН" -H "Content-Type: application/json" ^
  -d "{\"venue\": 1, \"date\": \"2026-10-30\", \"hours\": [18, 19]}"
```

## Подключение Flutter

Адрес сервера зависит от того, где запущено приложение:

| Где запущено приложение | Адрес сервера |
|---|---|
| Chrome (Flutter Web) | `http://127.0.0.1:8000` |
| Android-эмулятор | `http://10.0.2.2:8000` |
| Телефон по Wi-Fi | `http://<IP компьютера>:8000`, сервер запускать так: `python manage.py runserver 0.0.0.0:8000` |
